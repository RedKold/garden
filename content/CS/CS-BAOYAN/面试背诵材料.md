# 一、课程介绍

## 操作系统

### Q1：进程和线程的区别？
进程是资源分配的基本单位（独立地址空间），线程是 CPU 调度的基本单位。同一进程内线程共享代码段、全局数据、堆、打开的文件，但各有自己的栈和寄存器。线程切换比进程切换代价小，因为不需要切换地址空间。

### Q2：进程地址空间里有什么？
内核地址区 + 用户区：代码段（text）、数据段（.data/.bss）、堆（向上增长）、共享库映射区、栈（向下增长）。参考笔记「进程的地址空间」。

### Q3：进程间通信（IPC）有哪些？
管道（pipe）、命名管道（FIFO）、消息队列、共享内存、信号量、信号、socket。其中共享内存最快，但要自己加同步。

### Q4：死锁的四个必要条件？如何处理？
互斥、占有且等待、不可剥夺、循环等待。处理：死锁预防（破坏任一必要条件）、死锁避免（银行家算法）、死锁检测与恢复、鸵鸟策略（无视）。

### Q5：常用的进程调度算法？
FCFS、SJF/SRTF（短作业优先/最短剩余）、优先级调度（有饥饿风险）、时间片轮转 RR、多级反馈队列 MLFQ。MLFQ 综合了 SJF 与响应时间，是实际系统常用的折中。

### Q6：进程同步机制有哪些？
互斥锁（mutex）、自旋锁（spinlock）、信号量（semaphore）、条件变量（condition variable）、管程。锁用来互斥；信号量既能做互斥也能做同步（P/V 计数）；条件变量结合互斥锁用于"等一个条件"。

### Q7：条件变量怎么用？（笔记「条件变量模版 必考」）
必须配一个互斥锁和谓词条件，`while (谓词不成立) wait(cond, mutex)`，唤醒用 `signal/broadcast`。用 `while` 而不是 `if` 是为了防止虚假唤醒。典型应用是生产者-消费者。

### Q8：虚拟内存是干什么的？分页 vs 分段？
给每个进程一个独立、连续、大小超过物理内存的虚拟地址空间，通过页表映射到物理页。好处：进程隔离、按需加载、共享、可运行超过内存的进程。分页按固定大小（4KB）划分、无外部碎片、简单；分段按逻辑段（代码/数据/栈）划分、符合程序逻辑但有外部碎片；实际用「段页式」结合。

### Q9：页面置换算法？
FIFO（可能有 Belady 异常）、LRU（最近最少使用，近似最优，实现可用链表+哈希）、OPT（理论最优，淘汰最久不再使用）、Clock(二次机会) 近似 LRU、LFU(最少频率)。

### Q10：中断、系统调用、异常的区别？
中断：硬件/外设事件主动通知 CPU；系统调用（陷阱 trap）：用户程序主动请求内核服务，通过 `syscall`/`int` 指令发起，需要从用户态切换到内核态；异常：非法指令/除零/缺页等同步的硬件故障。共同点都是"控制转移到内核"，区别在触发来源是异步（中断）还是同步（陷阱/异常）。

### Q11：为什么要系统调用？用户态/内核态怎么切？
硬件给 CPU 提供特权级（Ring0/Ring3），用户态不能直接访问硬件和内核资源，必须通过系统调用这一"入口"进入内核态。切换通过 CPU 的 trap 机制，保存用户态现场（寄存器、栈指针、CS/EFLAGS），跳到内核处理程序，完成后返回用户态恢复现场。

### Q12：文件系统怎么做「崩溃一致性」？（笔记 Crash consistency）
落盘要保证原子性，避免断电中途造成不一致（如"写完数据但 inode/目录没更新"）。方案：先写数据再写元数据、**日志（journal）** 先记意图再提交、写时复制（CoW）/日志结构（LFS）、soft update 等。典型例子就是优雅的"写文件也要分多步，每一步都可能崩溃"。

### Q13：设备驱动程序的作用？
把具体硬件抽象成统一接口给内核/应用（读、写、ioctl），屏蔽硬件差异；驱动把设备结果交给操作系统处理。键盘、网卡、磁盘都各有驱动，连接用户程序和硬件。

## 计算机系统基础 ICS

### Q1：为什么用补码表示整数？如何取相反数？
补码让加减法统一（`A - B = A + (~B) + 1`），只用一套加法器，且符号位参与运算。取相反数：按位取反再加 1。减法与判断大小可统一处理。补码表示范围非对称（[-2^(n-1), 2^(n-1)-1]），但算术运算规则简单。

### Q2：CF 和 OF 标志位分别管什么？如何判断溢位？
CF：无符号数的进位/借位，管**无符号**溢出；OF：带符号数的溢出，管**有符号**结果是否超出范围（最高位进位与次高位进位异或）。做题口诀：CF 看"无符号是否错"，OF 看"两个加数同号且结果符号相反"。

### Q3：浮点数怎么用 IEEE 754 单精度表示？
1 位符号 + 8 位阶码（偏置 127，真值 = 阶码 - 127）+ 23 位尾数（隐含前导 1）。例：`0x40400000 = 3.0`。特殊值：0（阶码全 0，尾数 0）、非规格化数（阶码 0，尾数非 0，接近 0 的微小值）、无穷（阶码全 1，尾数 0）、NaN（阶码全 1，尾数非 0）。舍入默认向偶舍入。

### Q4：x86（IA-32）调用栈帧的结构？（笔记「栈帧必考」）
用 `%ebp` 作帧指针、`%esp` 作栈顶指针。进入函数：`push %ebp; mov %esp,%ebp; sub $N,%esp` 分配局部变量。栈帧从高到低：调用者的`%ebp` 被压栈 → 返回地址（在 `%ebp+4`）→ 实参（`%ebp+8` 起，第一个参数在 `%ebp+8`）→ 局部变量（`%ebp-%N`）。返回前 `leave; ret`。

### Q5：x86-64 与 IA-32 传参的主要区别？
IA-32 参数全在栈上（第一个参数在 `%ebp+8`）。x86-64 前 6 个整型/指针参数用寄存器传（`rdi, rsi, rdx, rcx, r8, r9`），第 7 个及之后才入栈；返回值用 `rax`。x86-64 还有 16 字节栈对齐要求。

### Q6：数据对齐（alignment）？例：`char` 后跟 `int` 怎么对齐？
对齐要求变量地址是其大小的倍数（`int` 需 4 对齐）。结构体按最大成员大小对齐，且总大小为对齐数的倍数。例：结构体先一个 `char` 再一个 `int`，`int` 从第 4 字节开始（`char` 后补 3 字节填充）。对齐利于 CPU 一次取走数据（否则可能两次访存）。

### Q7：链接时什么是符号解析、什么是重定位？（笔记「哪些东西需要重定位」）
每个 `.o` 是独立编译的（还不知道最终地址）。符号解析：把引用和定义绑定（区分全局/局部/外部）；重定位：把相对地址/符号引用改成运行时最终地址，并合并节。**重定位对象**：外部函数（`fopen、fread、fclose、sort` 等库函数）、全局变量（`rec_idx、const int rec_num` 等）、代码/数据段里的地址和字符串常量（如 `"rb"` 格式串）——都需要最终地址，所以在链接时重定位。

### Q8：静态链接 vs 动态链接？
静态链接在编译链接期把库代码整体拷进可执行文件，程序独立、但体积大、库更新需重编；动态链接在**运行时**加载共享库（`.so`），通过 PLT/GOT 惰性解析，体积小、多个进程可共享同一份代码。动态库若缺失会运行时报错。

### Q9：内存层次结构 / 缓存的作用？（笔记「内存层次结构」）
从快到慢、从贵到便宜：寄存器 → L1/L2/L3 → 主存 → 磁盘。缓存基于**局部性**：时间局部性（刚访问的最近会再访问）、空间局部性（相邻地址很可能一起访问）。评价：命中率、命中时间、缺失代价；映射方式有直接、组相联、全相联；写策略有写直达/写回。

### Q10：虚拟内存里页表、TLB、缺页各是什么？
页表把虚拟页号映射到物理页号（多级页表省空间）；TLB 是页表的"转译后备缓冲"，快表缓存最近映射以加速；缺页（page fault）是页不在内存，OS 从磁盘加载并可能做页面置换。局部性保证 TLB/页表工作良好。

### Q11：什么是异常控制流（ECF）？异常 vs 中断？
异常控制流：程序控制流不再顺序执行，由硬件/内核事件引起跳转。异常是**同步**的（除零、缺页、非法指令），中断是**异步**的（外设、时钟、键盘）。故障（fault）处理后可重启，终止（abort）直接终止进程。

### Q12：缓冲区溢出为什么会崩溃？如何防御？
如果数组越界写入，可能覆盖栈上的**返回地址**，函数返回时跳到攻击者地址 → 控制流劫持，直接崩溃或执行恶意代码。防御：栈金丝雀（canary）检查、栈不可执行（NX/DEP）、地址随机化（ASLR）、边界检查。

### Q13：I/O 与文件系统（笔记「IO」）？
设备通过固定地址的寄存器/内存映射 I/O 访问，数据搬运可用轮询、中断或 **DMA**（不经 CPU）。文件在系统里是 fd + 打开文件表，读/写/关闭/lseek；进程的文件描述符 → 打开文件表项 → inode。

# 二、算法介绍

## 常见排序

### 复杂度与稳定性速查表
| 排序 | 平均 | 最坏 | 最好 | 空间 | 稳定 |
|---|---|---|---|---|---|
| 冒泡 | O(n²) | O(n²) | O(n) | O(1) | 稳定 |
| 插入 | O(n²) | O(n²) | O(n) | O(1) | 稳定 |
| 选择 | O(n²) | O(n²) | O(n²) | O(1) | 不稳定 |
| 快排 | O(n logn) | O(n²) | O(n logn) | O(logn) | 不稳定 |
| 归并 | O(n logn) | O(n logn) | O(n logn) | O(n) | 稳定 |
| 堆排 | O(n logn) | O(n logn) | O(n logn) | O(1) | 不稳定 |
| 计数 | O(n+k) | O(n+k) | O(n+k) | O(k) | 稳定 |

### Q1：快排的思想与复杂度？
分治：选基准（pivot），一趟划分使左边 <= 基准、右边 >= 基准，再递归两边。平均 O(n logn)、最坏 O(n²)（原数组有序 + 固定基准）。优化：随机基准/三数取中、小区间用插入排序。**不稳定**，原地（递归栈 O(logn)）。快排是 OJ 里默认 `sort` 的实现基础。

### Q2：归并排序的思想与复杂度？
分治：先把数组对半递归排序，再合并两个有序子数组保持有序。O(n log n)，无论数据如何都稳定；**稳定**，但需要 O(n) 额外空间（合并用）。适合链表排序、外部排序。

### Q3：堆排序的思想与复杂度？
把数组建成最大堆，反复把堆顶（最大）移到末尾并调整堆。建堆 O(n)，每次调整 O(logn)，总 O(n logn)，**不稳定**，原地 O(1)。额外用途：`priority_queue` 即基于堆，用来求 Top-K / 第 K 大。

### Q4：插入、选择、冒泡一句话比较？
- 插入：把当前元素插入前面有序区，基本有序时最快 O(n)，稳定；
- 选择：每趟选最小放到前面，交换次数少但比较次数固定，不稳定；
- 冒泡：相邻逆序就交换，可提前结束，稳定。


### Q5：非比较排序？
计数排序 O(n+k)（值域小）；桶/基数排序（按位分桶）。都是线性但受值域/位数限制，一般面试问"排序题要求 O(n)"时用它们。

## Dijkstra

### Q1：算法思想？
**单源最短路**、贪心、只适用于**非负权**图。维护 `dist[]`，每次从"未确定集合"中取出当前 `dist` 最小的点 u，用它的边**松弛**（更新）邻点 v：`if (dist[u]+w < dist[v]) dist[v]=dist[u]+w`。直到所有点确定。

### Q2：复杂度与实现？
朴素实现 O(V²)（直接扫全找最小）。堆（优先队列）优化后 O((V+E) logV)，实际用 `priority_queue` 存 `(dist, 点)`，每次取堆顶（若过期跳过）。有向、无向都可，前提是边权非负。

### Q3：为什么不能处理负权？
因为贪心"一旦确定就不再改"，负权边可能让后面出现更短的路径（例如先走的 u 其实不是最短路）。**负权用 Bellman-Ford（O(VE)）或 SPFA；有负环则无最短路。**



### Q4：和 BFS 的关系？
边权都相等（如无权图）时，Dijkstra 退化为 BFS，因此 BFS 可用来求无权图最短路 / 最少步数。

## Prim / Kruskal

### Q1：什么是最小生成树（MST）？
在连通带权图里，选 n-1 条边连成树且总权最小。两种算法都基于**切割性质**：一个顶点集合到其补集之间的最小权边一定属于某棵 MST。

### Q2：Prim 算法？
从任一顶点出发，维护"已在树中的点集"，每次加入连接树内与树外点的**最小边**对应顶点，重复到所有点入树。稠密图用数组 O(V²)，稀疏图用堆 O(E logV)。类似 BFS/Dijkstra 的边扩展。

### Q3：Kruskal 算法？
把边按权从小到大排序，依次尝试加入；用**并查集**判断是否形成环（两端点不在同一集合就加入并合并）。很适合稀疏图，O(E logE)，关键是排序+并查集判环。

### Q4：两者对比？
Prim 从点扩展，适合**稠密**图（边多）；Kruskal 从边贪心，适合**稀疏**图（边少）。都能得到总权最小；若图不连通，Kruskal 实际生成的是最小生成森林。
