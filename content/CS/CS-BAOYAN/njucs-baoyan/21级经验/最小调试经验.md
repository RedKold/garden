#### 为什么需要它
* 1.在准备机试的过程中，想必都会遇到这样一个问题：不同平台的 Online Judge 的模式不一样，好难调试啊；
* 2.谁也无法确定到自己上机的时候，会遇到什么样的编程环境，如何调试代码，以及它们是否称手；
* 3.平时的编译环境可能不够严格，比如`Werror`不一定打开了。

所以此处提供一个`minimal`的makefile，以提升练习过程中的编码、调试体验。

**重要的是**：它不依赖任何IDE，只有最基础的一些utils（make, gdb和g++），玩过它一次之后你就能理解IDE提供了哪些动态的支持（计算机世界没有魔法），不管遇到什么样的真实上机环境，你都可以快速的在考场上搭建起一个自己舒适的测试环境。

不那么重要的是，njucs似乎有兼顾算法和工程测试的趋势，好的编程习惯（不仅仅是编码）可能会是他们想要的。

最不重要的是，尽管我看起来把这一套东西玩得很顺畅了吧，我的工程题并没有ak (24夏令营机试：100 + 0 + 37)，所以此文权当抛砖引玉了。

```Makefile
ifeq ($(NAME),)
$(error Should make in each lab's directory)
endif

MEM_CHECK := true
UB_CHECK  := true

SRCS   += $(shell find . -maxdepth 1 -name "*.cpp")
DEPS   := $(shell find . -maxdepth 1 -name "*.h") $(SRCS)
INPUT  := $(shell find . -maxdepth 1 -name "input") 

CFLAGS += -ggdb3 -std=c++11 -Wall -Werror -Wno-unused-result -Wno-unused-value -Wno-unused-variable -Werror=uninitialized

ifeq ($(MEM_CHECK),true)
CFLAGS += -fsanitize=address
endif

ifeq ($(UB_CHECK), true)
CFLAGS += -fsanitize=undefined
endif


$(NAME): $(DEPS)
	g++ -m64 $(CFLAGS) $(SRCS) -o $@ $(LDFLAGS)

$(NAME)-ans: $(DEPS)
	g++ -m64 $(CFLAGS) -DCHEAT $(SRCS) -o $@ $(LDFLAGS)

run: $(NAME)
	@./$(NAME)

input-run: $(NAME)
	@cat $(INPUT) | ./$(NAME)

debug:$(NAME)
	gdb -x init.gdb $(NAME)

compare:$(NAME) $(NAME)-ans
	@echo "=== My Ans ==="
	@cat $(INPUT) | ./$(NAME)
	@echo "=== AC Ans ==="
	@cat $(INPUT) | ./$(NAME)-ans

clean:
	rm -f $(NAME) $(NAME)-ans
```

#### 使用方法
这个makefile的可扩展性非常强，大家完全可以依照个人习惯进行魔改，此处分享个人的使用方法：

目录结构:
```plain text
.
├── Makefile -- 上文的makefile
├── README.md
├── leetcode
│   ├── array
│       ├── 209
│           ├── Makefile -- 可以定制针对每个题的内容，至少要把根目录下的makefile include进来
│           ├── README.md
│           ├── Solution.h
│           ├── init.gdb
│           ├── input
│           └── main.cpp
└── luogu
    ├── 104
        ├── P1125
            ├── Makefile
            ├── README.md
            ├── input
            └── main.cpp
```

说明：
* 在每个题目的子目录下，直接输入`make run`即可运行
* 如果是luogu刷题，可以直接在`main.cpp`编写；如果是leetcode刷题，可以直接在`Solution.h`编写
* 如果题目有输入，则可以把测试输入放在子目录的`input`文件中，并在调试的时候选择`make input-run`
* 如果需要调试，则需要编写子目录下的`init.gdb`，并使用`make debug`选项
* 如果leetcode需要特殊的结构体`TreeNode`，可以自行创建一个`TreeNode.h`放在任何你觉得正确的地方，比如我 就放在的leetcode - <题目类型>下，这样做这一类题的时候都只需要`#include "../TreeNode.h"`
* 默认打开了`undefine behavior`和`memory`的运行时检查，可以通过`make run UB_CHECK=false`来关闭你觉得不需要的部分

一个更完整的例子是我[个人的仓库](https://git.nju.edu.cn/jiayunchen/alg-coding)。



#### 什么？居然要我用gdb调试？！
原生gdb的使用还是比较恶心的，说实话，但是我实际上只用到了`b main`，`p array`，`c`，`wa x`这些非常简单的命令，所以还是可以试着学一下的。

但是gdb非常强大，它可以用python脚本注册命令，所以非常好的调试体验（超级轻量级的自定义就可以媲美、超越沉重的IDE）也是可以很轻松实现的，有兴趣可以看一看这个[gdb-dashboard](https://github.com/cyrus-and/gdb-dashboard)。
