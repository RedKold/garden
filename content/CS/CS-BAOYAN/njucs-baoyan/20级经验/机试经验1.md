# 机试经验

笔者参加了 2023 年 NJUCS 开放日硕士场的机试, 获得了一个还不错的分数, 下面仅就机试谈谈笔者的理解

## 基本形式

NJUCS 的机试一般是 2 个小时, 3 道题, 每题 100 分, 题面是英语, 题目难度较大

使用 Sharif Judge 作为 OJ, C/C++ 开启 `O2`, 使用 C++11 标准, 可以使用万能头 `bits/stdc++.h`

题目类型多为 OI 模式, 即需要撰写包含输入和输出的完整程序代码, 但 2023 年预推免出现了一道类似高程 OJ 的题目, 需要你实现一个带有模板参数的类

在 2023 年开放日硕士场的机试中, 因考生人数众多, 在考试中有一段时间 OJ 负载过大, 提交后需要数十分钟才能看到结果, 很折磨心态, 最终本场机试延时半小时

机试环境为 Windows 10, 可以使用 VS, DevC++, VSCode, 和一些笔者不认识的 IDE. 配有 MinGW 环境, 可以命令行敲 `g++` 指令. 笔者使用 VSCode 完成机试, 装有 C/C++ 插件, 可以点右上角编译运行, 但是不带 `O2` 参数. VSCode 无法对使用万能头的文件进行代码高亮和补全, 但可以编译 (有参加预推免的同学反馈说预推免机试并没有配 VSCode 的环境)

根据笔者的不完全统计, 在开放日硕士场拿到学硕优营的同学的机试分数大致在 160\~280, 拿到专硕优营的同学的机试分数大致在 100\~220

## 签到题

一般来说, 机试都会有一道思维难度较低的签到题作为第一题, 但做出来仍需要一定的编程基础

2023 年开放日博士场和预推免的签到题均为模拟题, 预推免的题目是在一个有障碍物的棋盘上根据输入的指令模拟机器人的行为 (前进若干格/破坏前方若干格的障碍物/...), 开放日博士场的题目是模拟自动机, 难度不大, 但需要小心细节

开放日硕士场的签到题是一道基础的数据结构题: 根据多叉树的先序和后序遍历还原这棵树, 输出这棵树每层最右侧的节点

本题难度不大, 可参考 [力扣889](https://leetcode.cn/problems/construct-binary-tree-from-preorder-and-postorder-traversal/) 和 [力扣199](https://leetcode.cn/problems/binary-tree-right-side-view/) , 但根据笔者的调查, 本题的得分率并不理想, 很多人只拿了 40 分. 笔者认为主要可能有以下两个原因

一. 对 C++ 常用 API 不熟悉

本题的输入格式并非标准的 OI 题格式: 两行, 每行若干个空格分隔字符串, 第一行表示先序遍历, 第二行表示后序遍历

输入中没有告诉你每行多少个字符串, 为了处理这种输入, 我们需要一次读取一整行, 然后按空格分割. 一些只会 `scanf` 和 `cin` 的经典选手直接懵逼, 只能凭着暧昧的记忆乱敲一些 `gets` 或 `getline`, 即使试出了正确写法, 也耽误了不少时间. (有同学反馈说用 `gets` 好像会 RE)

对于这种输入格式, 笔者建议使用 `std::getline` 读取一整行的内容, 再使用 `stringstream` 进行分割, 如下:

```c++
string line, token;
getline(cin, line);
stringstream ss(line);
while (ss >> token) { ... }
```

事实上, 这种非标准输入的题目在各地机试并不鲜见, 笔者在参加 SJTUCS 夏令营的机试时遇到过一道输入不光是行内字符串个数不确定, 行数也不确定的题目.

考场上没有手册可以查, 因此需要大家提前掌握一些常用 API, 尤其是对于使用 DevC++ 这种代码补全不完善的 IDE 的同学. 除了上面的输入输出, 笔者建议大家至少要熟悉 `vector`, `(unordered_)map`, `priority_queue` 等常用 STL, 以及算法库中的 `sort`, `lower_bound` 等常用函数, 有事没事多看看 [cppreference](https://zh.cppreference.com)

二. 将算法转换为代码的能力有所欠缺

本题建树算法想必各位在复习 408 时都接触过, 但实际写代码时可能会遇到各种各样的细节问题, 比如本题中树的数据结构选取, 找子树对应区间的时候的下标处理等. 看似简单的一道题, 想要写对所需要考虑的细节可能比一般的算法题还多. 能否在限时, 甚至评测机抽风的高压环境下快速, 正确地 A 掉本题 (或至少拿到 80 分), 是制胜的关键

本题有同学反馈本地自己测试都过了, 交上去全是 RE. 笔者认为这可能是因为本地和 OJ 的优化选项不同, 本地 VSCode 右上角执行是不开 `O2` 的, 而 OJ 开启 `O2` 可能会让数组越界或变量未初始化等 UB 产生运行时错误 (UB 在 `O0` 时是可能不出错的). 请各位注意 (笔者在 T3 就因为这里栽了坑, 万幸卡了一会儿就反应过来可能是优化的问题)

最后, 本题有一个很恶心人的测试点 -- 空树: 无输入. 这种测试点就不闭强求了

一般来说签到题最好争取在 40 分钟左右拿到 80\~90 分. 后面两题再用暴力骗个 40 分, 总分有个 120+, 就有希望 WL 前排或者专硕. 如果能完整做出一道题再骗点分, 总分有个 200+, 就有希望冲击学硕了

## DP

NJUCS 的机试很喜欢出 DP, CSDN 上的往年经验里也提到过这点. 今年开放日的硕士场和博士场都出了两道 DP, 且均是一道常规 DP, 一道状压 DP

先说常规 DP, 题目如下:

- 博士场 T2: 最长递增子序列变体, [力扣 354](https://leetcode.cn/problems/russian-doll-envelopes/) (本题同⼤⼩的可叠放)
- 硕士场 T3: 01 背包变体, 物品有 `c` 和 `v` 两个属性, 给定常数 `K`, 给出满足 `sum(v) / sum(c) == K` 条件下 `sum(v)` 最高的选法

博士场 T2 的解法请参照力扣. 硕士场 T3 则需要将等式变形为 `sum(v - c*K) == 0`, 从而将问题转换为容量是 `v - c*K`, 价值是 `v` 的 01 背包. 容量要求定值的 01 背包和一般的 01 背包仅初始化有所不同, 此处不再赘述. 此外还需要注意本题的"容量"可能是负数, 需要给数组下标加偏移量

仅就此来看, 这两题都属于中等难度的算法题, 想拿学硕的同学要尽量做到 A 掉这种题, 中等水平的同学也不能放弃, 要学会找到这种题的次优解:

- 博士场 T2 可以以能否叠放为边建 DAG 图, 然后拓扑排序, DAG DP, 能拿 50 分
- 硕士场 T3 可以使用较为暴力的布尔 DP, `bool dp[N][C][V]` 代表前 `n` 个物品能否凑出 `sum(c)` 为 `C` 且 `sum(v)` 为 `V`, 能拿 80 分

事实上, 在布尔 DP 的基础上再优化两步, 先空间压缩消去 `N` 这一维, 再使用 `bitset` 和位运算进行加速, 能直接 A 掉

再看状压 DP, 题目如下:

- 博士场 T3: [力扣 LCP 69](https://leetcode.cn/problems/rMeRt2/) (本题目标字符串为 `welcometonju`)
- 硕士场 T2: [洛谷 2774](https://www.luogu.com.cn/problem/P2774) (本题其实是网络流问题, 但状压 DP 可以拿 80 分, 故也归为此类, 状压解法参考 [洛谷 1896](https://www.luogu.com.cn/problem/P1896))

状压 DP 是 NJUCS 完全不教的内容, 我也没什么好说的, 基本思想可以参考 [OI Wiki](https://oi-wiki.org/dp/state/), 剩下的只能说多刷多练吧. 至于网络流, 我只能说祝你幸福

## 其他

如果只有上面, 那么准备 NJUCS 的机试只需要嗯刷算法题, 尤其是 DP 就行了, 但预推免的 T2 和 T3 相当于两个闪亮的耳光. T2 是让你实现带模板参数的 `HashMap` 类. T3 是实现一个简单语言的解释器, 语句有打印, 赋值, 循环 (次数是常数且循环体内只有赋值) 三种, 表达式有加法和常数乘变量两种, 还需要实现简单的循环优化

T2 容易因为不熟悉模板等 C++ 语法而倒在编译错误上, 且两题写起来都比较耗费时间, 不少人没写完时间就到了, 最终得分好像也不是很好看

目前尚不清楚这种出题风格的改变是仅仅一时兴起还是会延续下去, 这类题比较难以准备, 只能建议大家平时多熟悉 C++ 语法特性, 多磨练自己的代码能力, 提高写码速度

## 总结

1. 多看 [cppreference](https://zh.cppreference.com), 熟悉 C++ 语法特性和常用 API
2. 多刷题! 洛谷力扣刷起来! 一定要尽早开始刷! 重点刷算法和 DP, 积累各种题型的经验
3. 平时多动手写代码, 锻炼代码能力, 提升敲代码的速度和代码表达算法的精度
4. 考前去机房踩踩点, 熟悉一下机房电脑的操作手感和环境配置
5. 如果时间不够的话, 多看看题单也是好的, 看看题, 想几分钟, 再看题解, 争取接触多种题型, 万一考试就碰上了呢

笔者平时没有刷题的习惯, 不过幸好代码能力比较强, 采用考前两周突击题单的方式, 来不及做题就不动笔, 只看题思考再看题解, 争取积累题型, 博闻强识, 祈祷考试时碰上. 除了洛谷的官方题单, 笔者因为会日语, 还看了日本 [AtCoder](https://atcoder.jp/home) 的 [DP题单](https://atcoder.jp/contests/dp/tasks) (题面有日语和英语, 题解是日语) 和 [典型90问题单](https://atcoder.jp/contests/typical90/tasks) (只有日语). 笔者运气不错, 看到的题里有利用 `bitset` 加速的 DP 和状压 DP 的题目, 希望大家也能在考前碰到能用在考题上的思路
