### 二、访问 Cache 时，主存地址应该如何划分？代码 Cache 的总容量是多少位？


**主存地址划分**：

Cach 数据区 `8KB`, 可以容纳 `8KB / 64B = 8*2^10 / 2^6 = 8 * 2^4 = 128` 个主存块，
2 路组相联映射，则一共 64 行，每行 2 个 set
块内 offset 需要 `log（64B）` =`6 bit`,  组号（组索引）需要 `6bit`，剩下的为 tag
则划分：
```
|	tag		|	set		|	offset	|
|	20bit	|	6bit	|	6bit	|
```


[[ics - section 6 内存层次结构 memory hierarchy#理解 Cache 的总容量问题]]

代码 Cache 的总容量：
32bit 的地址，有 6bit offset， 6bit set， 1bit `lru`, 1bit `valid`, ~~1bit `dirty bit`~~(没有 dirty，直写法)

假设每行一个 LRU
`64 * 1 + 128* (1(valid) + 1(dirty) + 20 + 64*8) = 68288`

假设每块对应的一个 LRU
`128*(1 + 1 +20(tag) + 64*8) = 68352`



### 三
第 18 行指令的源操作数采用什么寻址方式？第一次执行该指令时，源操作数的有效地址为多少？读取该指令过程中是否发生 TLB 缺失和缺页？为什么？读取该指令过程中是否发生 Cache 缺失？为什么？用 300 字左右简述该指令的执行过程。（25 分，若能结合题目中给出的具体例子清楚描述 IA-32/Linux 中的地址转换过程，则额外加 10 分）

18: `mov 0x804a064(, %eax, 8), %eax`
	**寻址方式**：比例变址+偏移量
	[[ICS - Section 3 程序的转换和指令系统#寻址方式 Addressing Model|寻址方式]]	
- **注意**：偏移量放在括号前，比例变址的*系数*三元组的最后一个，作用于中间的，基址是第一个参数
- `a(b, c, d) = *(a + b + c*d)`


第一次执行：读代码知道 `%eax` 是 `i`，且 `0x804a064` 是 `rec_num` 的首地址
第一次执行，`i=0`, 所以有效地址是 `0x804a060`

读取该指令过程不会发生 TLB 缺失和缺页。系统中没有其他用户进程在执行

页大小为 4KB, `4KB = 2^12 bit`, 则该有效地址的后 12bit 是页内偏移。高 20bit 是页号。
`0x804a060` 的页号是 `0x804a`，而之前指令 8 已经有对该页号地址的访问了 `0x804a060`，所以该虚拟页已经加载到了主存。所以不会 TLB 缺失和缺页。

读取该指令不会发生 Cache 缺失，因为其和 17 行指令映射到了同一个 cache，则在 18 行指令的时候，该 cache 组一定已经从主存加载了数据了。所以不会发生 cache 缺失

**执行过程**：
- Instruction Fetch:
	- 根据*指令地址*`0x8048577` 的高 20bit `0x8048` 访问 TLB 得到物理地址，然后根据物理地址访问 Cache 命中，取出指令，
- 进行译码，得到需要访问的有效地址 `0x804a064`
- 执行: 根据 `0x804a` 虚页号访问 TLB
	- 如果 TLB 访问命中，则取出物理页框号和低 12bit 合成为物理地址；
	- 如果 TLB 缺失，则从虚拟页表中寻找
		- 根据高 20bit 的虚拟页框号寻找对应页表项
			- 如果 `valid=1`，则页命中，将对应的物理页框调入 TLB，根据低 12bit 的 offset 访问数据
			- 否则，进入页缺失 `Page Fault` 处理流程
				- 页缺失，则进入*异常处理*，系统进入内核态，
	- **得到物理地址后**，进入 Cache 查找。
		- 如果 Cache hit，则写入数据到 `%eax`
		- 如果 Cache miss，则到主存中根据物理地址调入 Cache，如果调入 Cache 的对应 entry 已经存储了有效地址，则根据 LRU 原则替换，设 `valid=1` ，填写新的标记字段。
			- 写数据到 `%eax`

### 四
从反汇编代码中的哪条指令可看出 INDEX 的长度？`sizeof(INDEX)` 为多少？编译器如何确定 INDEX 所占字节数？

---

从 `11 movzbl 0x804a060(, %eax, 8), %eax` 可以看出 INDEX 的长度，因为其比例变址的比例为 `8`，而此条指令执行的是对数组的访问，故 INDEX 结构体的长度为 `8`，即 `sizeof(INDEX)=8`
编译器根据对齐原理确定。该结构体 `index` 包含两个成员，`sizeof(unsigned char)=1`, `sizeof(RECORD*)=4`, IA-32 一次取 4 字节，故对齐让 `unsigned char` 也占 4（插入 3 字节的空），总共是 `sizeof(INDEX)=1+3+4=8`
