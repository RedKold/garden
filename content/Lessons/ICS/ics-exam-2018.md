## 五. 可执行文件

**段故障**类型号 13，信号名 SIGSEGV
- 检测到发生段故障，IA-32 采用段页式的虚拟地址管理。先查询段描述符表将 48 位逻辑地址转化为线性地址，通过查询页表将线性地址转化为物理地址，在 MMU 进行地址转换，若发现用户访问了不该访问的页面，或权限违规，则建设到保护性错，产生 13 号中断
- CPU 根据 13 号中断，找到 IDT 中的 13 号表项，CPU 保存用户进程的现场，将用户栈的信息保存到内核栈，当断点 (CS:EIP) 和机器状态（EFLAGS）保存到内核栈顶。发生故障的线性地址保存到 CR2 中，最后将 IDT 表项中的段选择符和偏移地址分别装入 CS 和 EIP 中，转到段故障处理程序执行
- Linux 采用信号机制处理。`general_protection` 发送一个 SIGSEGV 信号给用户进程，然后返回到用户进程执行。用户接收到一个信号，会转到 SIGSEGV 对应的信号处理程序去执行，该信号处理程序在屏幕上输出"segmentation fault"之后终止程序运行

`5b - 1d = 80+11 - (16+13)=91 - 29 = 62`
`offset = 目标地址 - call的下一条指令地址 = 0x804841d - 0x804845b = -0x3e = 0xffffffc2`
后四个字节依次 c2 ff ff ff (little-endian)

## 八
Cache 大小为 16KB，4-way connected可以存放
`16KB / (64B * 4) = 16 * 2^10 / (2^6 * 2^2) = 2^6 = 64组`
组内偏移为 `log(64) = 6bit`, set 需要 `6bit`，高 20bit 为 tag
虚页地址 32bit，虚页大小 4KB，页内地址 `log（4*2^10）=12`, 虚页号 20bit
